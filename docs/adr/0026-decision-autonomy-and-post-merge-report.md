# Decision autonomy and post-merge decision report

**Status:** accepted — 2026-06-17

## Context

The overlord historically surfaced a large volume of judgment calls to the user (the Overmind) for confirmation — most acutely during the local and GitHub review-remediation cycles, where each planner-escalation, diminishing-returns advisory, version-bump-type inference, and remediation-approach choice became an interrupt. Many of these were decisions the overlord could make safely on its own: the recommended action was contained, reversible, and carried no architectural or safety blast radius. Surfacing them anyway traded the overlord's autonomy for live oversight the user did not need to exercise, and buried the genuinely consequential decisions in the noise.

The design recorded here shifts the default posture: judgment calls the overlord previously surfaced for confirmation are now taken on the user's behalf and recorded, leaving only genuine ambiguity-with-risk for the user. The normative mechanics — the tier membership lists, the 2x2 cells, the promotion-gate categories, the disposition vocabulary, the journal entry shape, and the post-merge report trigger conditions — live exclusively in `plugin/governance/decision-autonomy.md` as the authoritative runtime home. This ADR records the hard-to-reverse, surprising-without-context decisions and their rationale; the governance doc executes them. The pointer is one-way ADR → governance.

## Decision

1. **Two decision tiers split always-surface from auto-decide.** Tier-A decisions (all safety rails, router ambiguity, resume/version-skew doors, brood strain approval, retry-exhausted tool errors, genuine fact-needed blockers, and ALL merge recommendations) are ALWAYS surfaced, exactly as before this posture existed. Tier-B decisions (planner-escalation routing, diminishing-returns early-exit, autonomous validation remediation, inferable version-bump type, root-cluster zoom-out routing, and confident remediation-approach choices) are auto-decided and journaled by default.

2. **An Autonomy 2x2 governs every Tier-B decision: recommendation strength (strong | weak/none) crossed with the promotion gate (clean | trips).** Strong recommendation + clean gate → DO THE WORK NOW (`did-now`). Weak/no recommendation + clean gate → DEFER-with-scope as a tracked follow-up (`deferred`). Any recommendation + gate trips → SURFACE (`surfaced`). A confident fix is never downgraded to a deferred follow-up; defer is the fallback for the ABSENCE of a strong recommendation, not a substitute for one.

3. **The promotion gate evaluates the RECOMMENDED action, not the option set.** The gate trips — forcing a surface — only when the recommended action is irreversible, carries architectural blast radius, or is safety-relevant (any Destructive Fix category 1-10 per `plugin/governance/safety-rails.md`). A heavy or architectural ALTERNATIVE being on the table does NOT promote the decision: if the recommended action is contained and the gate is clean, the overlord acts on it even though a bigger option exists.

4. **The decision journal is RECORDED JUDGMENT made observable, not new determinism.** Each Tier-B decision (and, for a complete audit trail, each Tier-A surface) is appended as one entry to `event.outputs.decisions[]` on the bounding state-result event — the same sanctioned free-form `event.outputs` write the proactive recurrence-origin marker already uses. This introduces no new workflow state, no workflow-graph change, no new run status, and no routing through `hivemind:mark-intent-fallback`. This follows the ADR-0025 precedent: judgment made observable after the fact over GitHub/ledger ground truth, not a new control-flow primitive. `decisions[]` is a free-form `outputs` key, not a new required ledger field; the canonical `event.outputs` shape is single-sourced in `plugin/references/run-ledger-schema.md`.

5. **A deferred post-merge decision report ALWAYS fires for runs that auto-decided.** After the PR for a run merges, the overlord surfaces a report recounting every decision it made on the user's behalf, rendered in the CONSUMER project's ubiquitous language. The report is deferred-on-merge: it is produced not at merge time but on a subsequent session start, when the Resume-On-Start scan derives an AWAITING-REPORT run (a PR exists, the journal carries at least one entry, and the report file does not yet exist) and observes the PR as `MERGED` or `CLOSED`. The report FILE's existence in the run dir is the SOLE idempotency marker — there is NO ledger marker, no new `run.status` value, and the run-status enum is unchanged. A run whose journal holds only `surfaced` entries produces no report.

6. **This ADR SUPERSEDES ADR-0003.** Planner escalation during review loops is no longer an immediate hard stop that returns to the user. It is a Tier-B decision auto-routed to the cerebrate remediation state and journaled, surfacing only when the promotion gate trips (which, being architectural by construction, it typically does for a genuine approach-level zoom-out).

## Considered Options

| Option | Rejected because |
|---|---|
| Surface everything — keep the status quo where every judgment call is an interrupt | Buries the genuinely consequential decisions in a high-volume stream of safe, contained ones; the review cycles in particular generate enough planner-escalation, advisory, and approach choices that the user's oversight is spent on decisions the overlord can make safely. The signal-to-noise cost outweighs the oversight benefit |
| Auto-decide without any record | Removes the user's ability to audit what was decided on their behalf, defeating the trust required for the autonomy shift; an unrecorded autonomous decision is indistinguishable from a silent scope expansion |
| Persist a new run-status / ledger marker for the post-merge report | Duplicates an idempotency signal the report file already provides, adds a new `run.status` value and persistence surface, and couples report state to the ledger when GitHub PR state plus file presence already determine it — the same single-source-of-truth reasoning ADR-0025 applied to the recurrence ledger |

## Consequences

- **More overlord autonomy at the cost of reduced live oversight, mitigated by the always-fired post-merge report.** The trade-off is deliberate: the overlord now acts on contained Tier-B decisions without interrupting the user, and the user's oversight moves from synchronous (confirm each call live) to asynchronous (review the full recounting after merge). The mitigation is structural — the report ALWAYS fires for any run that auto-decided, recounting each decision as situation / options / trade-offs / decision / why, so no autonomous decision escapes eventual review.
- **The merge action always stays with the human.** The overlord NEVER merges; ALL merge recommendations are Tier-A and always surfaced. Autonomy never extends to merging — it covers only the contained judgment calls along the path to a mergeable PR.
- **The promotion gate is evaluated against the recommended action, producing deterministic routing.** A single judgment per decision — is the recommended action irreversible, architectural, or safety-relevant — routes it to auto-take or surface. A heavy alternative on the table does not change that routing, which keeps confident contained fixes from being spuriously promoted.
- **The journal adds observability without new determinism.** Because `decisions[]` rides the existing free-form `event.outputs` path, the workflow graph, run-status enum, and ledger required-field set are all unchanged. The decision trail is reconstructable from the ledger event, consistent with how ADR-0025 made recurrence state observable over ground truth rather than via a new persisted artifact.
- **ADR-0003's immediate-stop rule is retired.** Planner escalation joins the Tier-B set and is journaled like any other auto-decision, surfacing through the promotion gate rather than as an unconditional mid-loop hard stop.
