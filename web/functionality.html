01 — Install

Install inside Claude Code

Run these two commands inside an active Claude Code session. No other install step is required. 

/plugin marketplace add https://github.com/brenpike/hivemind.git
/plugin install hivemind@brenpike

03 — Per-project setup

Per-project setup

1. Enable in .claude/settings.json

Add two keys to your project's .claude/settings.json. The agent key sets the overlord as the session default. Without it, Claude Code starts with the default agent and the overlord is only reachable on-demand — bypassing the workflow guarantees. 

{
  "enabledPlugins": {
    "hivemind@brenpike": true
  },
  "agent": "hivemind:overlord"
}

Or run the one-shot setup skill to apply these keys automatically and add .hivemind/ to your project's .gitignore: 

/hivemind:seed-hive

The setup skill creates the .hivemind/ directory at runtime for ephemeral plans, handoffs, and checkpoints, and gitignores it so it is never committed.

1a. Optional: seed a least-privilege permission allowlist

Pass seed_allowlist=yes to pre-populate a recommended set of permissions.allow entries — read-only helpers like echo, grep, jq, and scoped git read subcommands. Entries are appended-if-absent; existing entries are never overwritten or removed. 

/hivemind:seed-hive seed_allowlist=yes

For prompt-free local Codex review, also add your Codex cache path to the gitignored .claude/settings.local.json: 

"Bash(node /path/to/.claude/plugins/cache/openai-codex/codex/*)"

Replace /path/to/ with your actual home directory path. The codex/* wildcard covers all Codex CLI entry points so the entry does not need updating when Codex is upgraded.

Upgrading an already-seeded project. A project seeded by an earlier plugin version may still carry a literal Bash(node /path/to/.claude/plugins/cache/openai-codex/codex/*) line in its committed .claude/settings.json. The /path/to/ placeholder was never expanded there, so the rule matches nothing — delete it by hand. Re-running /hivemind:seed-hive will not re-add it; the merge is union append-if-absent and never removes, so the fix stops new and repeat seeds but does not clean up an existing file.

04 — Agents

Agents

Six specialized agents. Each owns a distinct role. All skills are invoked namespaced as hivemind:<agent>.

Agent Role What it does
hivemind:overlord Orchestrator Default agent. Coordinates all work, owns git workflow, branch and PR decisions, versioning decisions, and external review routing. Never writes code. Your main interface.
hivemind:cerebrate Strategist Research and implementation planning. Read-only — no file writes. Scans the territory and produces the directive the swarm executes.
hivemind:drone Builder Implementation within explicitly assigned file scope. The workhorse of the swarm.
hivemind:changeling Shaper Presentational UI/UX work within explicitly assigned file scope. Reshapes how things look and feel.
hivemind:local-reviewer Reviewer Pre-PR iterative Codex review with self-owning fix delegation at sonnet tier. Runs before a PR is opened.
hivemind:github-reviewer Post-PR worker Stateless fix-mode worker: deep-fetches and classifies post-PR feedback, applies fixes, pushes, and resolves threads. Dispatched by hivemind:github-review-loop.
05 — Skills

Skills

All skills are invoked using the namespaced form hivemind:<skill-name>.

Skill Purpose
hivemind:creep-spread Analyze project artifacts and generate a populated CONTEXT.md (or CONTEXT-MAP.md for multi-context repos) with domain terms extracted from code, docs, and config.
hivemind:molt Commit a completed phase, milestone, version bump, or review-remediation item — the checkpoint commit skill.
hivemind:create-working-branch Create or confirm a compliant working branch before implementation begins.
hivemind:adaptation-cycle Run a pre-PR local Codex review on the current branch diff. Invocable directly by users or via hivemind:local-reviewer.
hivemind:github-review-loop Watch a PR in the main session and dispatch the fix-mode github-reviewer per actionable event — owns the post-PR review loop.
hivemind:open-plan-pr Open a pull request after completion, validation, and versioning gates pass.
hivemind:plan-interrogation Interactive plan interview — challenges a plan against the project's domain model, sharpens terminology, and updates documentation as decisions crystallise.
hivemind:create-handoff Generate an optional session-resumption handoff doc from a plan.
hivemind:plan-to-prd Turn an interrogated plan into a committed WHAT-only PRD.
hivemind:prd-to-issues Slice a PRD into vertically-sliced, brood-ready GitHub issues.
hivemind:seed-hive One-time project setup: write required .claude/settings.json keys (enabledPlugins + default agent) and add .hivemind/ to .gitignore.
hivemind:tdd Implement features using Test-Driven Development (TDD) with the red-green-refactor cycle — invoke only in a context that can modify source and test files.
hivemind:spawn-brood Dispatch parallel overlord sessions — spawns N Claude Code instances in separate git worktrees via tmux.
hivemind:brood-status Check status of all active brood sessions — reports per-strain tmux session state, branch existence, and PR status.
hivemind:zoom-out Zoom out for broader context — maps relevant modules and callers using the project's domain glossary vocabulary.
hivemind:improving-architecture Read-only architecture analysis — emits a ranked refactoring blueprint of deepening opportunities (shallow → deep modules) for testability and AI-navigability
hivemind:refactor-to-depth Execution skill that performs a behavior-preserving deepening refactor via a refactor-under-green loop — the in-implementation counterpart to the read-only improving-architecture blueprint
06 — The Pipeline

The Lifecycle

A task flows from you through a chain of specialists. Each hand-off is explicit: the cerebrate produces a directive; drones and changelings build the essence; the adaptation cycle closes the loop before shipping.

  1. 01
    You give the overlord a task.

    The overlord is your single point of contact. It owns everything that follows.

  2. 02
    The cerebrate scans the territory and returns a directive.

    Read-only research agent. Produces the implementation plan the swarm executes.

  3. 03
    The overlord spawns specialists — drones and changelings — phase by phase.

    Each specialist gets an explicit file scope. They build in isolation, preventing scope drift.

  4. 04
    Each phase produces essence — knowledge carried forward.

    Handoff documents capture decisions and state so the next specialist starts with full context.

  5. 05
    An adaptation cycle reviews the work before shipping.

    Local Codex review runs on the branch diff. Findings are classified; fixes are delegated back to the drone or changeling.

  6. 06
    A PR is opened when the swarm stabilizes.

    The overlord opens the PR. Post-PR review feedback is handled by the github-review-loop skill.

You
 └─▶ Overlord
      ├─▶ Cerebrate       (plan)
      │    └─▶ Directive
      │
      ├─▶ Drone / Changeling  (build)
      │    └─▶ Essence
      │
      ├─▶ Adaptation Cycle  (review)
      │    ├─▶ Codex findings classified
      │    └─▶ Fixes delegated back
      │
      └─▶ PR opened
           └─▶ github-review-loop  (post-PR)
07 — Parallel Execution

Brood Mode

When the work is big enough, the overlord splits it into independent strains and dispatches a brood — multiple parallel sessions, each running its own full lifecycle in a separate git worktree. The overlord enters hatchery mode — monitoring from home base while each strain evolves independently.

How it works

  • ◆ The cerebrate decomposes work into independent strains — no shared state between them.
  • ◆ Each strain runs its own full overlord → cerebrate → drone/changeling pipeline in a tmux session.
  • ◆ Each strain lives in its own git worktree and produces its own branch and PR.
  • ◆ The overlord stays in hatchery mode — monitoring the brood from home base, available as an on-demand helper.
hivemind:spawn-brood hivemind:brood-status 
You
 └─▶ Overlord  (hatchery mode)
      └─▶ Cerebrate  (decompose)
           │  "3 independent strains detected."
           │
           ├─▶ Strain A  ─┐
           │    └─▶ own branch, own PR │
           ├─▶ Strain B  ─┤  parallel
           │    └─▶ own branch, own PR │
           └─▶ Strain C  ─┘
                └─▶ own branch, own PR
08 — Framework Signals

Signals

Named states the swarm broadcasts. Each maps to a clear action.

🔥

Flare

Urgent — agent hit something it cannot resolve alone. The overlord stops, surfaces the problem, and asks you how to proceed.

Requires human input
⚡

Reflex

Simple task — the overlord recognizes it as trivial and skips the cerebrate, spawning a drone directly for a faster result.

Fast path
🧬

Mutation Decay

Two fixes are fighting each other — a break-fix-break loop. The swarm halts. You decide which direction to take.

Conflict detected
↻

Adaptation Cycle

Review in progress — the swarm is running local Codex review and stabilizing before opening the PR. May iterate multiple rounds.

Review in progress

10 — Companion Plugins

Companion Plugins

All companions are optional. Hivemind works without them. When installed, each unlocks additional capabilities.

🧠

claude-mem

Optional cross-session memory and continuity. When installed, the cerebrate reads claude-mem memory via the MCP search tool before every plan. Writes happen through automatic capture — no write tool needed.

GitHub ↗
Optional
🔎

codex

Local and GitHub-integrated Codex code review. Enables the local-reviewer agent (pre-PR) and the github-review-loop skill (post-PR). If not installed, local review steps are skipped gracefully. 

/plugin marketplace add https://github.com/openai/codex-plugin-cc.git
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
Optional
🕯

caveman

Token-compressed communication. When installed, all framework agents output in caveman ultra mode — dramatically reducing token usage while preserving full technical accuracy. 

"enabledPlugins": { "caveman@caveman": true },
"pluginConfigs": { "caveman@caveman": {
  "options": { "defaultLevel": "ultra" } } }
